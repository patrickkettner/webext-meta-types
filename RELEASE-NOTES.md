# v1.1.2

## Summary

This release is a naming and correctness pass, not a new feature. Chrome, Firefox, and Safari named the same concept differently in 319 places; every private name now resolves to one canonical public name. 32 members that a shared interface used to ship as required now ship optional, each with a `@note` naming who lacks them. Duplicate union arms are down from 121 to 92. The Safari column loses 26 claims for members WebKit hides from Manifest V3 extensions. `npm run check` gains three gates since v1.1.1: `verify:widening`, `verify:gecko-pin`, `verify:names`.

Five of those rows are alias collapses, where Firefox declared a public `type X = _X` alias: `_manifest._CommonDataCollectionPermission`, `_manifest._OptionalPermissionNoPrompt`, `_manifest._PermissionPrivileged`, `contextMenus._ContextType`, `menus._ContextType`. Seven underscore names remain by curated verdict, not omission: `dns._ResolveFlags`, `webRequest._HttpHeaders`, `_manifest._OptionalPermission`, `_manifest._PermissionNoPrompt`, `_manifest._ThemeType`, `cookies._RemoveReturnDetails`, and `_eval`, chrome-types' own reserved-word re-export inside `devtools.inspectedWindow` (two overloads).

Three pairs stay apart on purpose, not in this table: `permissions.Permissions`/`AnyPermissions` (different value spaces for contains() vs request()), `cookies.Cookie`/`_RemoveReturnDetails` (remove() returns an identification record, not a Cookie), and `userScripts.RegisteredUserScript`/`UpdateRegisteredUserScript` (register() requires `js`, update() does not). Same name, two concepts, no merge. A namespace with one voter adopts its alias-group sibling's canonical, so `contextMenus` and `menus` share `CreateProperties`.

## Namespaces That Lost Their Chrome Tag

`browserAction`, `pageAction`, and `_manifest` now ship `@supported Firefox` only; `mimeHandlerPrivate` is gone from `dist/index.d.ts` entirely. chrome-types declares none of them: `index.d.ts:64-65` introduces `browserAction` only behind a comment flagging it as a compatibility stub for the MV3 `action` API, and the other three don't appear as namespaces at all. Seven Chrome overrides on these four namespaces, plus one on `runtime.getManifest` (untyped there, `(): {[name: string]: any}`), are deleted.

## Dev-Channel Notes

Six namespaces chrome-types marks dev-channel-only now say so: `dns`, `processes`, `sockets.tcp`, `sockets.tcpServer`, `sockets.udp`, and `system.network` each carry a namespace-level `@note Chrome: dev channel only`, repeated on every Chrome-provenance member inside. `dist/metadata.json` records it as a `channel` field next to `supported` (e.g. `{"chrome": "dev"}`). `grep -c 'Chrome: dev channel only' dist/index.d.ts` reports 120.

## Optional Members

`dist/index.d.ts` widens a member to optional whenever the browsers that declare it are a subset of the interface's own `@supported` set; before this release the merge widened only against itself. 32 members change from required to optional, each with a `@note` naming who lacks it (`tabs.Tab.frozen`: only Chrome declares it on a three-browser `Tab`, so it now ships `frozen?: boolean`). `npm run verify:widening` checks this against `dist/index.d.ts` and every pruned single-browser file's own upstream.

## Merged Unions

Duplicate union arms are down from 121 to 92: sorting union arms before comparing collapsed 22 Chrome/Firefox enum unions on its own (121 to 99), then stripping the enclosing namespace before comparing an arm to its bare name collapsed seven members and nineteen Safari overloads onto their Chrome/Firefox twins (99 to 94), and the Safari repin removed the `browserAction.openPopup` and `pageAction.openPopup` unions with the namespaces' Safari members (94 to 92). The collapsed pairs are `tabs.MutedInfo`, `permissions.onAdded`/`onRemoved`, `runtime.onConnect`/`onConnectExternal`, and `storage.onChanged`. `npm run ratchet:unions` pins the count.

Patch corpus: 6 files changed since v1.1.1, 101 lines added, 139 removed. `patches/*.json` holds 178 entries and 248 overrides now (one per entry per `overrideChrome`/`overrideFirefox`/`overrideSafari`/`overrideShared` field present). `verify:patches` proves every override load-bearing by removing it and diffing the output; the last run reported LOAD-BEARING 248, INERT 0.

## Gates

`npm run check` runs three more gates than v1.1.1, chained right after `check:pruned`: `verify:widening`, `verify:gecko-pin`, `verify:names`. Full chain: `typecheck`, `test:unit`, `build`, `check:artifacts`, `check:pruned`, the three new gates, `verify:override-vocabulary`, `verify:override-members`, `enforce:zero-any`, `test`, `verify:dist`, `verify:artifacts`, `verify:derivation`, `verify:patches`, `verify:evidence`, `ratchet:unions`.

## Known Gaps

- The Safari support tags were checked against Safari 26.4 by enumerating `browser.*` from a Manifest V3 extension. 26 members the package claimed for Safari are hidden from every MV3 extension by WebKit's `isPropertyAllowed`: all of `browserAction` and `pageAction`, `tabs.executeScript`, `tabs.getSelected`, `tabs.insertCSS`, `tabs.removeCSS`, and `extension.getURL`. `safari-webextension-types` now reads those gates from WebKit at its generation ref and no longer declares them; this release pins that version. The enumeration sees names only. Parameter shapes, dictionary members, optionality, and anything behind a permission the test extension did not request are still unchecked against a running Safari. Four names Safari exposes that the package does not claim (`runtime.getDocumentId`, `scripting.ExecutionWorld` as a runtime object, `storage.local.setAccessLevel`, `storage.sync.setAccessLevel`) are not added; each needs a WebKit citation first.
- `safari-webextension-types` is generated from WebKit commit `0136fa2b` of 2026-08-15, later than the Safari Technology Preview 250 cut (`41655c48`, 2026-07-26), so a member WebKit added between those commits carries a Safari tag before any Safari build has it. `offscreen` is the one such case found and is excluded by hand: WebKit added it in commit 1d214176 on 2026-08-07.
- `npm run verify:lag` derives the upstream-lag label against the Gecko schemas at `FIREFOX_143_0_RELEASE`, the tag pinned in `gecko-pin.json` and checked by `verify:gecko-pin`: LAG 27, NO-NOVEL-MEMBERS 6, UNVERIFIABLE 26 keep their label on trust, not a schema comparison.
